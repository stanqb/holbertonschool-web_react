# Webpack

## Description

This project is an introduction to **Webpack**, the module bundler used across modern JavaScript applications. It is part of the Holberton School front-end curriculum (`holbertonschool-web_react`).

Through four progressive tasks, the project goes from a bare-bones Webpack installation to a fully configured development environment with multiple entry points, asset handling, code splitting, and a live dev server.

## Learning Objectives

- How to set up Webpack for a basic project
- What entry points, output, and loaders are
- How to add plugins to a Webpack configuration
- How to split a codebase into modules
- How to set up a development server
- How to use tree shaking and code splitting to reduce bundle size

## Requirements

- Node.js and npm installed
- Each task folder is self-contained, with its own `package.json` and dependencies

## Tasks

### Task 0 - Basic setup

A minimal Webpack installation with no custom config file. Uses jQuery to append three paragraphs to the page body. The bundle is generated in `dist/`.

- **Dependencies:** `jquery`
- **Dev dependencies:** `webpack`, `webpack-cli`

### Task 1 - Using a config file

Introduces a `webpack.config.js` file. Builds a dashboard page with a click counter button, using the Lodash `debounce` function (500 ms delay) to prevent spam clicking. Output is `bundle.js` in the `public/` folder, built in production mode.

- **Dependencies:** `jquery`, `lodash`
- **Dev dependencies:** `webpack`, `webpack-cli`
- **Build:** `npm run build`

### Task 2 - Adding CSS and images

Extends the config with loaders for stylesheets and images. Adds a `#logo` element backed by the Holberton logo, and styles the counter to sit to the right of the button in bold. Images are optimized so the build stays under the recommended asset size limit.

- **Additional dev dependencies:** `css-loader`, `style-loader`, `file-loader`, `image-webpack-loader`

### Task 3 - Dev server, modules and tree shaking

Splits the codebase into three independent modules (`header`, `body`, `footer`), each with its own JavaScript and CSS. Configures three entry points producing `[name].bundle.js` files, enables inline source mapping, cleans the build folder between builds, auto-generates the HTML file, and splits shared vendor code (jQuery, Lodash) into separate chunks. A development server runs on port **8564**.

- **Additional dev dependencies:** `clean-webpack-plugin`, `html-webpack-plugin`, `webpack-dev-server`
- **Start the dev server:** `npm run start-dev` then open `http://localhost:8564/`

## Usage

Each task is independent. Move into the desired folder, install dependencies, then build:

```bash
cd task_1
npm install
npm run build
```

For task 3, start the development server instead:

```bash
cd task_3
npm install
npm run start-dev
```

## Notes

- Generated bundles (`dist/main.js`, `task_3/public/`) must not be committed to the repository.
- Each HTML page imports only the JavaScript generated by Webpack.
- Opening a generated HTML file should produce no error in the browser console.
